# Creating Compute in Azure Databricks

Azure Databricks provides managed compute resources to execute Apache Spark workloads for data engineering, analytics, and machine learning.

## 1. Introduction to Databricks Compute

Databricks compute provides the processing resources required to run notebooks, Spark applications, data pipelines, and queries.

The main compute options include:

- **Serverless Compute:** Databricks manages the underlying infrastructure, reducing the need for manual cluster configuration. Availability depends on the workload and workspace configuration.
- **Single-Node Compute:** Runs workloads on a single machine without separate worker nodes. Suitable for learning, small datasets, development, and lightweight data processing.
- **Multi-Node Compute:** Uses a driver and multiple worker nodes to distribute Spark workloads across machines. Suitable for larger datasets and parallel processing.

## 2. Create a Compute Resource

Navigate to **Compute → Create Compute** in the Databricks workspace.

Provide a name for the compute resource and configure the required settings.

- **Policy:** Determines which compute configurations are permitted.
- **Access Mode:** Controls how users and workloads access the compute resource and governed data.
- **Databricks Runtime:** Specifies the runtime environment, including the Spark version and supported libraries.

## 3. Single-Node vs Multi-Node Compute

### Single-Node Compute

- Uses a single machine for the driver and processing.
- Suitable for experimentation, small datasets, and learning PySpark.
- Has fewer configuration requirements than multi-node compute.

### Multi-Node Compute

- Uses a driver node to coordinate execution and worker nodes to process tasks.
- Supports distributed processing across multiple machines.
- Can use autoscaling to adjust the number of workers based on workload demand.

## 4. Important Compute Configurations

- **Node Type:** Determines the CPU and memory resources available per machine.
- **Driver Type:** Defines the resources used by the Spark driver.
- **Worker Nodes:** Specify the number of worker machines in a multi-node configuration.
- **Autoscaling:** Automatically adjusts the worker count between the configured minimum and maximum.
- **Photon Acceleration:** Provides accelerated execution for supported workloads.
- **Auto-Termination:** Automatically stops compute after a specified period of inactivity to help control costs.
- **Spot Instances:** May reduce compute costs where supported, but can be interrupted.

For this learning setup, a Databricks Runtime 17.3 LTS environment was selected, with a 20-minute inactivity timeout. The multi-node configuration used autoscaling between 1 and 4 workers.

## 5. Compute Quotas and Cost Management

- Azure subscription quotas can limit the number of available CPU cores.
- Choose an appropriate node type and worker count based on workload requirements.
- Use single-node compute for small experiments where distributed processing is unnecessary.
- Enable auto-termination to reduce unnecessary compute charges.
- Remember that auto-termination does not eliminate charges while compute is running.

If a quota warning appears, select a smaller configuration or request an increase in the applicable quota.

## 6. Key Learnings

- Understand serverless, single-node, and multi-node compute.
- Configure Databricks Runtime, node types, and access modes.
- Understand the roles of Spark drivers and worker nodes.
- Use autoscaling and auto-termination for workload and cost management.
- Identify how Azure CPU quotas affect compute creation.
